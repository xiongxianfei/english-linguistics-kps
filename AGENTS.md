# KPS 12 contribution guidance

## Key takeaway
Preserve canonical entity semantics, source limits and user-authorized publication boundaries.

## Summary
Read AUTHORING.md, spec/KPS12.md, SCOPE.md and CHECKS.md before editing. KPS 12 is the active local draft profile; legacy/kps9 is immutable historical input, not the current authoring contract.

## Work rules
Read affected entities, claims and dependencies. Do not infer identity, role or subject domain from a path. Edit canonical JSON and uniquely owned Markdown; regenerate derived views. Do not invent source passages, reviewer records, audio observations or learner outcomes. A legacy citation must not be promoted into claim-level evidence by automation.

## Checks and publication
Run actual checks and report failures. Never refresh a dependency baseline merely to silence a warning. Preserve the read-only permanent CI workflow, do not force-push shared branches, and do not merge or publish a release without authorization. Keep profile implementation status separate from scientific review.
